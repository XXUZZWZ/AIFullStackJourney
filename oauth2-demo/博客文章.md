# 深入理解OAuth2回调URL：通过实际演示看懂授权码模式

在现代Web应用中，OAuth2已经成为标准的授权框架。无论是使用GitHub、Google还是微信登录，背后都是OAuth2在工作。而回调URL（Callback URL）作为OAuth2授权码模式的核心组件，承担着安全传递授权码的关键作用。

## 什么是OAuth2授权码模式？

OAuth2是一个授权框架，允许第三方应用在无需用户凭据的情况下，获得对用户资源的有限访问权限。授权码模式是OAuth2最安全的流程，特别适用于Web服务器应用。

授权码模式的完整流程包括：
1. 客户端将用户重定向到授权服务器
2. 用户登录并同意授权
3. 授权服务器通过回调URL返回授权码
4. 客户端使用授权码换取访问令牌
5. 使用访问令牌访问受保护资源

## 回调URL的关键作用

回调URL是OAuth2流程中的"桥梁"，它确保授权码能够安全地从授权服务器返回到客户端。让我们看看实际的工作原理：

当用户点击"使用OAuth2登录"时，客户端会构建这样的授权URL：

```
http://localhost:3001/auth/login?
  response_type=code&
  client_id=demo-client&
  redirect_uri=http://localhost:3002/callback.html&
  scope=profile&
  state=random_string
```

其中，`redirect_uri`就是回调URL。用户授权成功后，授权服务器会将用户重定向到这个URL，并携带授权码：

```
http://localhost:3002/callback.html?code=AUTH_CODE&state=random_string
```

这个过程的安全要点：
- **预注册验证**：回调URL必须预先在授权服务器注册
- **完整匹配**：实际回调URL必须与注册的完全一致
- **一次性使用**：授权码只能使用一次，有效期很短

## State参数：CSRF攻击的防护利器

为了防止CSRF（跨站请求伪造）攻击，OAuth2引入了state参数。CSRF攻击试图利用用户的已登录状态，在用户不知情的情况下发起恶意请求。

State参数的工作原理：

1. **生成随机state**：客户端生成随机字符串并存储在sessionStorage
2. **请求时携带**：将state作为参数发送给授权服务器
3. **回调时验证**：验证返回的state是否与存储的一致

这确保了授权请求确实是由用户主动发起的，攻击者无法预测或伪造state值，因为浏览器同源策略阻止跨域访问。
