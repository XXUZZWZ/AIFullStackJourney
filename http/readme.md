## 版本特性

- Hypertext Transfer Protocol (HTTP)
- 讲清楚有那些版本

  - http 0.9 没有正式版本
  - 最早的版本，只支持 GET 请求,响应里只有 html 文本，没有 **header**
    请求
    GET /index.html
    响应
    响应格式：没有头部，直接就是 HTML 内容，比如：

  ```html
  <html>
    <body>
      Hello World
    </body>
  </html>
  ```

  - 只能传输简单网页，连图片 css js 都不能传
  - http 1.0
    - 有了 cookies 仍然能传输多种类型数据
    - 添加了 请求头 header , 能传输多种类型数据图片 等
    - 没次请求都要重新建立 TCP 链接
      - 开销浪费 ，同域名下的资源，一条路
      - 早期用户不多
      - http 基于请求响应的简单协议 TCP 链接 断开
    - HTTP/1.0 的升级理解为“真正的协议雏形”：
      - 请求和响应都有结构
      - 能传更多格式
      - 有状态码和错误提示
      - 但还不算高效，1.1 出现就是为了解决这些问题。

- http 1.1

  - 用户太多了，一定要解决 TCP 链接每次都重新建立的问题
  - 推出了长链接
    - Connection : keep-alive
    - 一个 TCP 可以处理多个请求，浏览器通过一个 TCP 链接连续请求页面 图片 脚本 等多个资源，服务器处理完后不会立即断开，而是保持连接，后期请求无需建立连接，节省时间和性能开销，提高加速速度。
  - 管道化 piplining
    - 运行同时发多个请求，但响应必须按顺序返回
    - 你使用支持管道化的浏览器，依次发送 获取首页 图片 1 2 3 无需等待前一个响应，但是服务器必须按顺序返回。
    - TCP 可靠的传输，确保通信的多个数据包，按顺序返回，全都按顺序返回 没有真的能并发， http 1.1 是顺序传输,是 http 协议导致的阻塞，tcp 其实已经准备好了
    - 队头阻塞，如果排在前面的资源的资源传输慢，后面的就没有办法传输
    - 数据分块传输 chunk
  - 性能优化
  - 路由懒加载，分包 ，动态加载
    - App.jsx Login.jsx
    - http 优化，图片懒加载
      js/css/img 过多要合并文件 同一个域名请求的并发上限是 6 个
    - base64 格式图片 html /css 文件里的，减少请求
    - 图表字体库 iconfont
    - 开启压缩
    - 使用多个域名？？？
      - 问题背景
        浏览器在 HTTP/1.1 里有一个限制：每个域名同时只能开 6 个 TCP 连接（不同浏览器数量略有差异）。
        如果一个网页要加载大量资源（HTML、CSS、JS、图片），6 个连接可能不够，导致请求排队，影响页面加载速度。
      - 解决思路
        多域名分片：把资源分布到不同域名上，比如：
        cdn1.example.com
        cdn2.example.com
        images.example.com
        浏览器认为是不同域名，就会分别为每个域名开 6 个 TCP 连接。
        这样总共可以同时开更多连接 → 并行加载更多资源，提升性能。
      - 静态资源 CDN 优化
    - 浏览器缓存使用是最快的，强缓存 和协商缓存

- http 2.0

  - 并发 多路复用
  - 一个 TCP 连接上并发多个请求 不在队头阻塞
  - 多路复用把数据拆成帧交错 成多个数据流，然后发送
  - 二进制数据帧
  - 所有的请求和响应都拆分成小数据帧，通过一个连接并发传输，每个帧都有编号，指定那个文件，服务气端和服务器端可以根据编号重组，无需排队，谁先准备好就谁先发，解决了 http 队头阻塞问题,此时阻塞来源于 tcp 层 传输失败导致。
  - 头部压缩 减少 header 传输
  - 服务器端推送 server push
  - 服务端可主动推送资源
  - 加速页面快速显示
  - 客户端要一个 index.html 服务器把相关的 app.js css 传给客户端缓存等 ，为了减少首轮返回，服务器会主动的 push 相关资源

- http 3.0
  基于 QUIC

- 都是为了更快的页面展示

## GET 和 POST 的区别

- 用途不同
  - GET 请求用来获取数据
  - POST 用来提交数据
    我在开发中会结合 Restful 协议 标准开发
  - PATCH /PUT 修改 DELETE 删除
  - OPTIONS 预检请求 HEAD 文件的信息
- 数据传输方式

  - GET url params 或 queryString 明文
  - POST 请求体 相对安全

- 安全性
  - GET 不安全 会被缓存
  - POST 相对安全，但是还是要启动 https 加密传输
- 数据长度限制
  - GET 受长度限制 ，2048 个字节 2kb 不适合传输大量数据
  - post 没有长度限制 ，适合大量数据传输 比如大文件上传
- 幂等性
  - GET 幂等性 ： 相同请求两次结果一样，返回的响应都一致
  - POST 非幂等性 ：可能创建新资源或修改
- 缓存和书签

  - GET 可以被浏览器缓存，可以收藏为书签
  - POST 不可以被浏览器缓存，不可以收藏为书签

- 状态码
  - GET 200
  - POST 201
