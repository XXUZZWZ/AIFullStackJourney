# Event Loop：浏览器渲染主线程的调度机制

## 定义

**Event Loop（事件循环）** 是浏览器中用于协调 JavaScript 执行、用户交互、页面渲染等任务的核心机制。它运行在 **浏览器渲染主线程** 上，通过一个持续不断的循环来调度各种任务的执行。

要理解 Event Loop，首先需要了解浏览器的基本架构：

- **浏览器进程**：负责管理整个浏览器的行为，包括多个标签页的协调、网络请求、用户界面绘制等。
- **渲染进程（如每个标签页）**：包含多个线程，其中最重要的是 **渲染主线程**，它负责执行 JavaScript、解析 HTML/CSS、计算样式、布局和绘制等任务。

在 Chrome 中，Event Loop 本质上是一个 `for(;;)` 的无限循环结构，不断检查各个任务队列是否有待处理的任务，然后按优先级顺序依次执行这些任务。

## 核心机制

Event Loop 的核心思想是：

> 根据不同类型的任务设置不同的优先级，按照优先级顺序从对应的任务队列中取出任务执行。

### 1. 任务类型与队列

浏览器中的任务主要分为两类：

#### 🟢 宏任务（Macrotask）

- 常见来源：`setTimeout`、`setInterval`、`requestAnimationFrame`、I/O 操作、UI 渲染等。
- 每次 Event Loop 循环处理一个宏任务。

#### 🔵 微任务（Microtask）

- 常见来源：`Promise.then`/`.catch`、`queueMicrotask`、`MutationObserver` 等。
- 微任务具有 **最高优先级**，会在当前宏任务结束后立即清空微任务队列。

### 2. 执行流程简述

完整的事件循环执行流程如下：

1. 执行一个宏任务（如从 `script` 或 `setTimeout` 队列中取出）。
2. 执行所有当前已入队的微任务，直到微任务队列为空。
3. 可能执行一些渲染更新操作。
4. 等待下一个宏任务到来，重复上述过程。

### 3. 优先级调度

不同任务队列之间存在优先级关系：

| 优先级 | 队列类型        | 示例                        |
| ------ | --------------- | --------------------------- |
| 最高   | Microtask Queue | `Promise.then`              |
| 中等   | Macrotask Queue | `setTimeout`, `setInterval` |
| 较低   | Rendering Task  | `requestAnimationFrame`     |

这意味着即使一个宏任务正在执行，只要微任务队列中有任务，它们也会被优先执行。

## 总结

Event Loop 是浏览器调度 JavaScript 异步行为的核心机制，它确保了页面响应性、任务有序执行以及资源合理利用。理解 Event Loop 不仅有助于写出更高效的代码，还能帮助排查异步执行顺序相关的问题。
