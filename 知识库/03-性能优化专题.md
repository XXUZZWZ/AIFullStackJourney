## 🎨 渲染性能优化

### 🔥 重排与重绘的本质

#### 理解重排与重绘
- **重要程度**: ⭐⭐⭐ 高频必考
- **知识点**:
  - 浏览器渲染流程（解析→构建→布局→绘制→合成）
  - 重排（Reflow）：重新计算布局
  - 重绘（Repaint）：重新绘制像素
  - 性能影响：重排 > 重绘 > 合成
- **代码位置**: `css/reflow/` - 重排详解
- **学习建议**:
  - P0: 理解什么操作会触发重排/重绘
  - P1: 掌握性能影响大小
  - P2: 学习浏览器优化机制

#### 🔥 哪些操作会触发重排？
- **常见操作**:
  - 修改元素尺寸 (width, height, padding, margin, border)
  - 修改元素位置 (left, right, top, bottom)
  - 获取尺寸信息 (offsetWidth, scrollHeight 等)
  - 添加/删除/修改 DOM
  - 修改字体大小
  - 改变窗口大小
  - 打印页面
- **代码参考**: `batjtmd/浏览器渲染原理/` - 详细列表

#### 🔥 优化策略：避免重排/重绘

**1. 使用 transform 替代 left/top 位置变化**
```javascript
// ❌ 不好 - 触发重排
element.style.left = '100px';

// ✅ 好 - 只触发合成
element.style.transform = 'translateX(100px)';
```
- **代码位置**: `css/animate/` - 动画最佳实践
- **性能提升**: 10-100 倍快

**2. 使用 opacity 替代 visibility 改变可见性**
```javascript
// ❌ 不好 - 可能触发重排
element.style.visibility = 'hidden';

// ✅ 好 - 只触发重绘
element.style.opacity = '0';
```

**3. 批量修改 DOM**
```javascript
// ❌ 不好 - 多次触发重排
for (let i = 0; i < 100; i++) {
  element.style.width = i + 'px';
}

// ✅ 好 - 只触发一次重排
element.style.cssText = 'width: 100px; height: 100px;';
```

**4. 使用 DocumentFragment 批量插入**
- **代码位置**: `performance/` - 详细实现
- **性能提升**: 5-10 倍

**5. 离线修改 DOM**
```javascript
// ✅ 好 - 先离线修改，再添加到 DOM
const frag = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  const div = document.createElement('div');
  div.textContent = i;
  frag.appendChild(div);
}
document.body.appendChild(frag);
```

**6. 缓存计算结果**
```javascript
// ❌ 不好 - 多次重排
for (let i = 0; i < 1000; i++) {
  element.style.width = element.clientWidth + 10 + 'px';
}

// ✅ 好 - 缓存计算结果
const width = element.clientWidth;
for (let i = 0; i < 1000; i++) {
  element.style.width = width + 10 * i + 'px';
}
```

**7. 使用 requestAnimationFrame 控制帧率**
- **代码位置**: `performance/` - requestAnimationFrame 使用
- **作用**: 与浏览器刷新率同步（60fps），避免卡顿
- **应用场景**: 动画、滚动、复杂计算

### 🔥 React 组件性能优化

#### React.memo - 组件记忆化
- **重要程度**: ⭐⭐⭐ 高频必考
- **用途**: 避免不必要的组件重新渲染
- **代码位置**: `interview/performance/` - 详细讲解
- **使用场景**:
  - Props 没有改变时，组件不重新渲染
  - 避免 Props 每次都生成新对象
- **最佳实践**:
  ```javascript
  const MyComponent = React.memo(({ data }) => {
    return <div>{data}</div>;
  });
  ```
- **注意事项**:
  - Props 比较使用浅比较
  - 避免每次传入新对象/数组/函数
  - 可自定义比较函数

#### useMemo - 值记忆化
- **重要程度**: ⭐⭐⭐ 高频必考
- **用途**: 缓存计算结果，避免重复计算
- **最佳实践**:
  ```javascript
  const expensiveValue = useMemo(() => {
    return computeExpensiveValue(a, b);
  }, [a, b]);
  ```
- **应用场景**:
  - 复杂的数据转换
  - 选择器创建
  - 派生状态
- **性能考虑**:
  - useMemo 本身有开销，只在计算确实昂贵时使用
  - 不要过度使用

#### useCallback - 函数记忆化
- **重要程度**: ⭐⭐⭐ 高频必考
- **用途**: 避免传递新函数引用导致子组件重新渲染
- **最佳实践**:
  ```javascript
  const handleClick = useCallback(() => {
    doSomething(a, b);
  }, [a, b]);
  ```
- **常见错误**:
  - 在所有地方都使用 useCallback（不必要）
  - 依赖数组配置错误
  - 与 React.memo 配合不当
- **黄金法则**: 只在函数作为 Props 传给优化过的子组件时使用

#### 虚拟列表优化
- **重要程度**: ⭐⭐⭐ 实战高频
- **适用场景**: 大列表渲染（1000+ 项）
- **核心原理**: 只渲染可见区域，滚动时动态加载
- **代码位置**:
  - `interview/virtural_list/` - 虚拟列表完全指南
  - `interview/virtural_list/vitrural-list-demo/` - 完整实现
  - `performance/虚拟列表实现.md` - 详细讲解
- **性能对比**:
  - 普通列表（1000 项）：初始化 2-3 秒
  - 虚拟列表：初始化 100-200ms
- **学习步骤**:
  1. 理解窗口计算原理
  2. 掌握 DOM 复用技巧
  3. 处理动态高度
  4. 优化滚动性能

#### React Fiber 优化
- **重要程度**: ⭐⭐⭐ 进阶
- **原理**: 增量渲染，可中断和恢复
- **代码位置**: `interview/react/fiber/` - Fiber 架构详解
- **性能优势**:
  - 任务优先级划分
  - 可中断渲染
  - 更好的响应性

## 📦 加载性能优化

### 🔥 资源加载优化

#### 1. 代码分割（Code Splitting）
- **重要程度**: ⭐⭐⭐ 高频必考
- **用途**: 减小初始包大小，按需加载
- **技术方案**:
  - 路由级分割：`React.lazy()`
  - 组件级分割：动态 import
  - 第三方库分割：webpack splitChunks
- **代码位置**: `performance/` - 代码分割详解
- **性能提升**: 初始加载时间减少 50-70%

#### 2. 路由懒加载
- **重要程度**: ⭐⭐⭐ 实战常用
- **实现方式**:
  ```javascript
  const Home = lazy(() => import('./Home'));
  const About = lazy(() => import('./About'));
  ```
- **预加载策略**:
  - 预加载下一页路由
  - 基于用户交互预测加载
- **代码位置**: `React/router-demo/`、`React/deep-router/` - 路由最佳实践

#### 3. 预加载与预连接
- **rel="preload"**: 预加载关键资源
- **rel="prefetch"**: 预加载非关键资源
- **rel="preconnect"**: 预连接 CDN
- **rel="dns-prefetch"**: 预解析 DNS
- **性能提升**: 减少 100-500ms 的加载时间

#### 4. 资源压缩与最小化
- **Gzip 压缩**: 文本内容压缩 60-80%
- **JavaScript 最小化**: 减小 40-60%
- **CSS 最小化**: 减小 30-50%
- **图片优化**: WebP、压缩、适配不同尺寸

#### 5. 使用 CDN
- **优势**: 内容分发，接近用户地理位置
- **缓存策略**: 将静态资源放在 CDN
- **性能提升**: 减少 50-200ms 的网络延迟

### 🔥 缓存策略

#### 强缓存（本地缓存）
- **Expires**: 绝对过期时间（HTTP/1.0）
- **Cache-Control**: 相对过期时间（HTTP/1.1）
  - `max-age`: 缓存最大时间
  - `public/private`: 公共/私有缓存
  - `no-cache`: 需要验证
  - `no-store`: 不缓存
- **代码位置**: `performance/cache/` 或 `前端网络/cache/` - 详细讲解
- **使用策略**:
  - 静态资源（JS/CSS）：长期缓存（1 年）+ 文件哈希名称
  - HTML：不缓存或短期缓存

#### 协商缓存（服务端验证）
- **ETag**: 资源内容指纹
- **Last-Modified**: 资源最后修改时间
- **工作流程**:
  1. 客户端发送 If-None-Match 或 If-Modified-Since
  2. 服务端对比，若未变更返回 304 Not Modified
  3. 客户端使用本地缓存
- **性能提升**: 避免重复下载，减少网络流量

#### 浏览器缓存类型
- **Memory Cache**: 内存缓存，快速但容量小
- **Disk Cache**: 磁盘缓存，容量大但速度慢
- **Service Worker Cache**: 离线缓存，自主控制
- **IndexedDB**: 大容量数据库缓存

### 🔥 脚本加载优化

#### async vs defer
- **无属性**: 阻塞 HTML 解析，立即执行
- **async**: 并行加载，加载完立即执行（不保证顺序）
- **defer**: 并行加载，DOM 解析完后执行（保证顺序）
- **推荐策略**:
  - 关键脚本：放在 `<head>` 中使用 defer
  - 非关键脚本：放在 `</body>` 前或使用 async
  - 第三方脚本：考虑使用 async

#### 动态脚本加载
- **适用场景**: 条件加载、运行时加载
- **性能优势**: 不阻塞初始渲染

## 📊 Web Vitals 优化

### 🔥 LCP - 最大内容绘制

#### 含义
- **定义**: 页面主要内容加载完成的时间
- **良好标准**: < 2.5s
- **代码位置**: `performance/` - Web Vitals 详解

#### 优化策略

**1. 优化关键资源加载**
- 使用 preload 预加载关键图片/字体
- 最小化 JavaScript 包大小
- 使用代码分割

**2. 优化服务端性能**
- 减少 TTFB（Time to First Byte）
- 使用 CDN
- 服务端缓存

**3. 优化客户端渲染**
- 使用服务端渲染（SSR）
- 减少 JavaScript 阻塞
- 优化大型 DOM

#### 测量方法
```javascript
const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log('LCP:', entry.renderTime || entry.loadTime);
  }
});
observer.observe({entryTypes: ['largest-contentful-paint']});
```

---

### 🔥 INP - 交互到下一次绘制

#### 含义
- **定义**: 用户交互到页面响应的延迟
- **良好标准**: < 200ms
- **包括**: 点击、键盘输入、指针交互

#### 优化策略

**1. 减少主线程阻塞**
- 分解长任务为多个短任务
- 使用 `requestIdleCallback` 处理低优先级任务
- Web Workers 处理复杂计算

**2. 优化事件处理**
- 使用事件委托
- 异步处理非关键逻辑
- 使用被动事件监听器

**3. 减少输入延迟**
- 预测用户交互
- 提前加载相关资源
- 使用乐观更新 UI

---

### 🔥 CLS - 累积布局偏移

#### 含义
- **定义**: 页面加载期间意外的布局变化
- **良好标准**: < 0.1
- **常见原因**: 图片/字体加载、广告插入、Cookie 横幅

#### 优化策略

**1. 预留空间**
- 指定图片和视频的宽高
- 预留字体空间
- 为动态内容预留空间

**2. 避免在顶部插入内容**
- 不在导航栏下方插入广告
- 使用固定位置的 Cookie 横幅
- 加载动画应该是非布局偏移的

**3. 使用 transform 动画**
- 避免使用影响布局的属性
- 优先使用 transform 和 opacity

#### 测量方法
```javascript
const observer = new PerformanceObserver((list) => {
  let cls = 0;
  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {
      cls += entry.value;
    }
  }
  console.log('CLS:', cls);
});
observer.observe({entryTypes: ['layout-shift']});
```

## 🗂️ 缓存策略

### 字段级缓存

#### localStorage vs sessionStorage
- **localStorage**: 永久存储（除非手动删除）
- **sessionStorage**: 会话存储（关闭标签页清除）
- **代码位置**: `javaScript/storage/` - 存储详解
- **适用场景**:
  - 用户偏好设置：localStorage
  - 临时数据：sessionStorage

#### IndexedDB
- **大容量**: 可存储数百 MB 数据
- **异步 API**: 不阻塞主线程
- **应用场景**:
  - 离线应用
  - 大型本地数据库
  - 缓存大量 API 响应
- **学习难度**: ⭐⭐⭐

#### Service Worker 缓存
- **离线工作**: 网络不可用时仍可工作
- **缓存策略**:
  - Cache First：优先使用缓存
  - Network First：优先网络，网络不可用时使用缓存
  - Stale While Revalidate：返回缓存同时更新
- **应用场景**: PWA、离线应用

## 💾 内存与垃圾回收

### 内存泄漏预防

#### 常见内存泄漏
1. **全局变量**: 意外创建全局变量
2. **未清理的定时器**: setTimeout/setInterval 未清理
3. **事件监听器**: 未移除事件监听器
4. **DOM 引用**: 保持对已删除 DOM 的引用
5. **闭包过度使用**: 闭包保持过多引用

#### 预防策略
```javascript
// ❌ 不好 - 未清理定时器
setInterval(() => {
  // 操作
}, 1000);

// ✅ 好 - 保存并清理
const timer = setInterval(() => {
  // 操作
}, 1000);
clearInterval(timer);
```

### WeakMap vs Map
- **代码位置**: `interview/es6/` - WeakMap 详解
- **WeakMap 特点**:
  - 键只能是对象
  - 键是弱引用，不计入垃圾回收
  - 适合缓存与 DOM 关联的数据
  - 适合类的私有属性
