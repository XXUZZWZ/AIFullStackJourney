## 🔨 构建工具

### 🔥 Vite vs Webpack

#### Vite 的优势
- **开发速度**: 极快的热更新（HMR）
- **启动速度**: 秒级冷启动
- **原生 ES Module**: 直接使用浏览器原生 ESM
- **配置简单**: 默认配置开箱即用
- **代码位置**: `vite/vite-demo/` - 实际演示

#### Webpack 的优势
- **生态成熟**: 插件和 loader 最丰富
- **功能完整**: 支持复杂的定制需求
- **兼容性**: 支持旧版浏览器
- **代码位置**: `vite/webpack-demo/` - Webpack 对比

#### 选择建议
- **新项目**: 优先考虑 Vite
- **维护项目**: 继续用 Webpack（成本考虑）
- **特殊需求**: 评估插件生态

### 🔥 Webpack 深入

#### 核心概念
- **Entry**: 入口文件
- **Output**: 输出配置
- **Loaders**: 文件转换（JS、CSS、图片等）
- **Plugins**: 扩展功能（压缩、提取 CSS 等）
- **Mode**: 打包模式（development/production）

#### 常用配置
```javascript
module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: '[name].[contenthash].js',
  },
  module: {
    rules: [
      {
        test: /\.jsx?$/,
        use: 'babel-loader',
        exclude: /node_modules/
      },
      {
        test: /\.css$/,
        use: ['style-loader', 'css-loader']
      }
    ]
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: './public/index.html'
    })
  ],
  mode: 'production'
};
```

#### 代码分割配置
```javascript
optimization: {
  splitChunks: {
    chunks: 'all',
    cacheGroups: {
      vendor: {
        test: /[\\/]node_modules[\\/]/,
        name: 'vendors',
        priority: 10
      },
      common: {
        minChunks: 2,
        priority: 5
      }
    }
  }
}
```

### 🔥 Vite 核心

#### Vite 特点
1. **极速 HMR**: 修改文件秒级更新
2. **按需编译**: 只编译被导入的模块
3. **ESM 原生**: 利用浏览器原生 ESM 能力
4. **开箱即用**: 无需复杂配置

#### 基础配置
```javascript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  },
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['react', 'react-dom']
        }
      }
    }
  }
})
```

## 🔄 代码转译

### 🔥 Babel 原理与配置

#### Babel 的作用
- **转译**: 将新版本 JavaScript 转为旧版本
- **Polyfill**: 补充缺失的功能
- **插件**: 支持 JSX、TypeScript 等

#### 基础配置
```javascript
module.exports = {
  presets: [
    ['@babel/preset-env', {
      targets: '> 0.25%, not dead',
      useBuiltIns: 'usage',
      corejs: 3
    }],
    '@babel/preset-react',
    '@babel/preset-typescript'
  ],
  plugins: [
    '@babel/plugin-proposal-class-properties',
    '@babel/plugin-proposal-decorators'
  ]
};
```

#### useBuiltIns 选项
- **false**: 不自动补充 polyfill（默认）
- **entry**: 手动引入 core-js，自动转为按需补充
- **usage**: 自动检测，只补充使用到的特性

#### 代码位置
- `interview/writeccode/polyfill/` - Polyfill 详解
- `interview/writeccode/` - Babel 转译原理

### 🔥 Polyfill 与 core-js

#### Polyfill 的必要性
- 旧浏览器不支持新特性
- 需要通过 polyfill 补充功能
- 增加包大小，按需补充是关键

#### 常见 Polyfill
```javascript
// Promise polyfill
if (!window.Promise) {
  window.Promise = PromisePolyfill;
}

// Array.prototype.flat polyfill
if (!Array.prototype.flat) {
  Array.prototype.flat = function(depth = 1) {
    return this.reduce((acc, val) => {
      if (Array.isArray(val) && depth > 1) {
        return acc.concat(val.flat(depth - 1));
      }
      return acc.concat(val);
    }, []);
  };
}
```

#### core-js 使用
```javascript
// .babelrc
{
  "presets": [
    [
      "@babel/preset-env",
      {
        "useBuiltIns": "usage",
        "corejs": 3
      }
    ]
  ]
}

// 无需手动 import core-js，Babel 会自动处理
```

## ✅ 代码质量

### 🔥 ESLint 配置

#### 基础配置
```javascript
module.exports = {
  env: {
    browser: true,
    es2021: true,
    node: true
  },
  extends: [
    'eslint:recommended',
    'plugin:react/recommended',
    'plugin:@typescript-eslint/recommended'
  ],
  parserOptions: {
    ecmaVersion: 'latest',
    sourceType: 'module',
    ecmaFeatures: {
      jsx: true
    }
  },
  rules: {
    'no-console': 'warn',
    'no-unused-vars': 'error',
    'react/prop-types': 'off',
    '@typescript-eslint/no-explicit-any': 'warn'
  }
};
```

#### 常见规则
- **no-unused-vars**: 禁止未使用的变量
- **no-console**: 禁用 console 输出
- **eqeqeq**: 必须使用 === 和 !==
- **curly**: 必须使用花括号
- **no-var**: 禁用 var，使用 let/const

## 📝 版本控制

### 🔥 Git 工作流

#### 基础命令
```bash
# 日常操作
git status          # 查看状态
git add .          # 暂存更改
git commit -m "msg" # 提交
git push           # 推送
git pull           # 拉取

# 分支管理
git branch         # 查看分支
git checkout -b feature/xxx  # 创建分支
git switch main    # 切换分支
git merge feature/xxx        # 合并分支
```

#### 分支策略
```
main (生产)
  ↑
  ├── develop (开发)
  │    ↑
  │    ├── feature/user-login
  │    ├── feature/payment
  │    └── bugfix/modal-close
  │
  └── release/1.0
       └── hotfix/security
```

#### 代码位置
- `interview/git/` - Git 详细讲解

### 🔥 Commit 规范

#### Conventional Commits 格式
```
<type>(<scope>): <subject>

<body>

<footer>
```

#### Type 分类
- **feat**: 新功能
- **fix**: 修复 bug
- **docs**: 文档更新
- **style**: 代码格式（不改逻辑）
- **refactor**: 重构
- **perf**: 性能优化
- **test**: 添加测试
- **chore**: 工程配置

#### 示例
```
feat(auth): 添加用户登录功能

- 实现登录表单
- 集成 JWT 认证
- 添加登录状态管理

Closes #123
```

## 🚀 部署与发布

### 🔥 持续集成与持续部署 (CI/CD)

#### GitHub Actions 示例
```yaml
name: Build and Deploy

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v2

    - name: Install dependencies
      run: npm install

    - name: Run tests
      run: npm test

    - name: Build
      run: npm run build

    - name: Deploy to Vercel
      env:
        VERCEL_TOKEN: ${{ secrets.VERCEL_TOKEN }}
      run: vercel --prod
```

### 📌 部署平台

#### Vercel
- **优势**: Next.js 优化、全球 CDN、自动部署
- **适合**: Next.js、静态网站、API
- **免费**: 支持免费部署

#### Netlify
- **优势**: 静态网站、无服务器函数、CMS 集成
- **适合**: 静态网站、Gatsby、Hugo
- **部署**: Git 自动部署

#### 云服务器
- **AWS EC2**: 完全控制，成本较高
- **阿里云、腾讯云**: 国内访问快
- **DigitalOcean**: 简单易用、成本低

### 🔥 依赖管理

#### npm vs pnpm vs yarn
| 工具 | 优势 | 缺点 | 适用场景 |
|-----|------|------|--------|
| npm | 官方、使用广泛 | 幽灵依赖、安装慢 | 个人项目 |
| pnpm | 快速、节省空间 | 生态较新 | 大型项目 |
| yarn | 可靠、快速 | 生态维护 | 稳定项目 |

#### 推荐最佳实践
```json
{
  "engines": {
    "node": ">=18.0.0",
    "npm": ">=9.0.0"
  },
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint src --ext .js,.jsx,.ts,.tsx",
    "format": "prettier --write src",
    "test": "jest",
    "test:watch": "jest --watch"
  }
}
```

### 🔥 开发效率工具

#### Husky + lint-staged
```bash
# 安装
npm install -D husky lint-staged
husky install

# .husky/pre-commit
#!/bin/sh
. "$(dirname "$0")/_/husky.sh"
npx lint-staged
```

```json
// package.json
{
  "lint-staged": {
    "*.{js,jsx,ts,tsx}": "eslint --fix",
    "*.{js,jsx,ts,tsx,json,css,md}": "prettier --write"
  }
}
```

#### 自动版本控制
```bash
npm install -D standard-version

# package.json
{
  "scripts": {
    "release": "standard-version",
    "release:minor": "standard-version --release-as minor",
    "release:major": "standard-version --release-as major"
  }
}
```
