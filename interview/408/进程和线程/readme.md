# 进程和线程

## 进程

### 定义

- 进程是操作系统资源分配的基本单位，是正在运行的程序
- 相当于一个工厂，每个进程拥有自己专属的资源（堆区、栈区、全局区、代码区）
- 操作系统为每个进程分配独立的内存空间

### 特点

- 独立性：每个进程都有自己的地址空间和执行环境 每个进程有自己的地址空间和执行环境
- 资源隔离：一个进程崩溃不会直接影响其他进程
- 状态：创建态、就绪态、运行态、阻塞态、终止态

## 线程

### 定义

- 线程是进程中执行运算的最小单元，是操作系统执行处理机制的基本单位
- 相当于工厂里的工人，工人可以共用工厂里的部分资源
- 每个进程至少包含一个线程

### 特点

- 轻量级：线程的创建和切换比进程更快
- 资源共享：同一进程内的线程共享进程的内存和文件资源
- 低切换成本：线程之间切换成本低，适合处理并发任务

## 死锁

### 定义

- 死锁是指多个并发实体（进程/线程）在竞争资源或相互通信时，因互相等待对方释放资源而造成的一种永久阻塞现象。

### 必要条件（同时满足才可能发生）

- 互斥：资源一次只允许一个进程/线程占有
- 不可抢占：资源在未使用完之前不能被强行剥夺，只能主动释放
- 占有且等待：已占有至少一个资源，同时又提出新的资源请求并等待
- 循环等待：存在进程/线程形成的循环资源等待链

### 例子

- 两把锁反序获取（Java 伪代码）：

  ```
  Object L1 = new Object();
  Object L2 = new Object();

  Thread A: synchronized(L1) { sleep(); synchronized(L2) { /* ... */ } }
  Thread B: synchronized(L2) { sleep(); synchronized(L1) { /* ... */ } }
  // A 持有 L1 等 L2；B 持有 L2 等 L1 => 循环等待
  ```

- 数据库事务死锁（InnoDB 示例思路）：
  - T1：UPDATE 表 SET ... WHERE id = 1; 然后 UPDATE ... WHERE id = 2;
  - T2：UPDATE 表 SET ... WHERE id = 2; 然后 UPDATE ... WHERE id = 1;
  - 两事务行锁顺序不一致，形成等待环。
- join/await 形成环：
  - T1 在关键路径等待 T2 完成；T2 又等待 T1 的信号，双方互等。

### 处理策略

- 预防（破坏必要条件）
  - 破坏互斥：尽量使用无锁/无共享结构（无锁队列、CAS）
  - 破坏不可抢占：允许资源可抢占或可回滚（数据库事务回滚）
  - 破坏占有且等待：一次性申请所有所需资源；失败则释放已占资源并重试
  - 破坏循环等待：对资源统一排序，只按升序申请
- 避免（动态判断是否可能进入不安全状态）
  - 银行家算法：在分配前根据最大需求与可用资源判断是否会进入不安全状态
- 检测与解除（允许死锁发生后再处理）
  - 周期性检测等待图或资源分配图中是否存在环
  - 解除方式：剥夺资源、回滚（撤销并重试）、终止部分或全部进程

### 常见示例

- 互相反序加锁：线程 A 持有锁`L1`再等`L2`，线程 B 持有`L2`再等`L1`
- 线程间同步错误：`join()`/`await`形成环形等待
- 数据库死锁：两事务对同一批行不同顺序加锁（如先锁行 A 再锁行 B vs 先锁 B 再锁行 A）

### 实战规避建议

- 对锁/资源建立全局有序规则，严格按顺序申请
- 缩小锁粒度与持有时间，避免在持锁期间进行阻塞操作（I/O、远程调用）
- 使用超时锁（如`tryLock(timeout)`）与退避重试策略
- 避免嵌套锁；必要时将临界区拆分
- 采用不可变数据结构、消息队列等尽量减少共享可变状态

## 进程与线程的区别

- 地址空间：进程有独立地址空间；同一进程内线程共享地址空间
- 切换开销：进程上下文切换较大；线程切换较小
- 通信方式：进程间通信（管道、消息队列、共享内存、套接字等）更复杂；线程间通信可直接读写共享内存，但需同步原语
- 资源拥有：进程拥有系统资源；线程主要拥有执行上下文（栈、寄存器）

## 并发与并行

- 并发：在同一时间段“交替推进”多任务（单核通过时间片轮转也可并发）
- 并行：在同一时刻“同时运行”多任务（多核/多机）

## 同步、互斥与临界区

- 互斥：同一时刻仅允许一个执行流进入临界区（锁、信号量的 P/V）
- 同步：在时间顺序上的协调与等待（条件变量、事件、Barrier）
- 临界区：访问共享资源的代码片段，应尽量短小且可预期

## 上下文切换与调度

- 上下文切换：保存并恢复 CPU 寄存器、程序计数器、栈指针等状态
- 调度策略：先来先服务（FCFS）、短作业优先（SJF/短剩余时间优先）、时间片轮转、优先级调度、多级反馈队列
- I/O 密集 vs 计算密集：I/O 密集适合更多线程以隐藏等待；计算密集线程数不宜超过 CPU 核数

## 进程间通信

- 常见 IPC：
  - 管道（匿名管道/命名管道）：父子进程或同机不同进程的单向/半双工通信
  - 消息队列：基于内核的消息缓存，支持多生产者/消费者与优先级
  - 共享内存：最高效，但需配合信号量/互斥量保证同步
  - 信号/信号量：事件通知与计数型同步原语
  - 套接字（Unix Domain/ TCP/UDP）：同机或跨机通信的统一抽象
  - 内存映射文件（mmap）：通过文件映射共享内存
- 特点：跨进程地址空间隔离，需内核参与或专用机制，序列化与同步成本更高。

## 线程间通信

- 同一进程内共享内存，通信方式更直接：
  - 互斥锁/读写锁/自旋锁：互斥与并发读优化
  - 条件变量/事件/Barrier：顺序与阶段性同步
  - 原子操作与 CAS：无锁读写与竞争减轻
  - 队列/Channel：基于消息的内存内通信
- 风险：数据竞争、可见性问题；需内存模型与正确同步保证有序与可见。

## 浏览器

- 多进程架构（以 Chromium 为例）：
  - Browser 进程：主控、UI、进程管理、网络调度（部分版本）
  - Renderer 渲染进程：每个标签页/站点实例通常对应一个或多个渲染进程
  - GPU 进程：统一 GPU 加速
  - 插件/扩展进程：隔离第三方代码
- 好处：
  - 稳定性：单个渲染进程崩溃不影响整体
  - 安全性：站点/渲染进程沙箱隔离，降低越权风险
  - 性能：多核并行，进程优先级与资源隔离
- 代价：
  - 进程数量与内存占用增加，跨进程通信（Mojo/IPC）成本更高
