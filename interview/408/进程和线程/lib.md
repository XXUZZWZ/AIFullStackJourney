# 进程和线程

## 进程

**定义**：

- 进程是操作系统资源分配的基本单位，是正在运行的程序
- 相当于一个工厂，每个进程拥有自己专属的资源（堆区、栈区、全局区、代码区）
- 操作系统为每个进程分配独立的内存空间

**核心特点**：

1. **独立性**：每个进程都有自己的地址空间和执行环境
2. **资源隔离**：一个进程崩溃不会直接影响其他进程
3. **状态**：创建态、就绪态、运行态、阻塞态、终止态

**举例**：

- 同时打开浏览器和网易云音乐，它们是两个独立的进程

## 线程

**定义**：

- 线程是进程中执行运算的最小单元，是操作系统执行处理机制的基本单位
- 相当于工厂里的工人，工人可以共用工厂里的部分资源
- 每个进程至少包含一个线程

**核心特点**：

1. **轻量级**：线程的创建和切换比进程更快
2. **资源共享**：同一进程内的线程共享进程的内存和文件资源
3. **低切换成本**：线程之间切换成本低，适合处理并发任务

**举例**：

- 在浏览器（一个进程中），一个线程负责下载文件，一个线程负责渲染页面

## 进程与线程的区别

| 比较维度     | 进程                                   | 线程                                       |
| ------------ | -------------------------------------- | ------------------------------------------ |
| **资源开销** | 创建成本高，需要分配内存空间和其他资源 | 创建成本低，只需少量额外数据结构           |
| **执行效率** | 切换成本高，适合处理独立任务           | 切换成本低，适合处理并发任务               |
| **隔离保护** | 相互隔离，有私有地址空间               | 共享进程资源，一个线程出错可能影响其他线程 |
| **通信方式** | 需要复杂的 IPC 机制                    | 通过共享内存直接通信                       |
| **执行环境** | 拥有独立的执行环境                     | 在进程的上下文中执行                       |

## 死锁

### 死锁定义

死锁是指两个或多个线程/进程在执行过程中，因争夺资源或彼此通信而相互等待，导致所有线程无法继续执行的现象。

### 死锁产生的四个必要条件

1. **互斥条件**：至少有一个资源必须处于一次只允许一个线程使用的状态
2. **请求和保持条件**：一个线程在请求资源时保持已获得的资源
3. **不可剥夺条件**：资源不能被强制从一个线程那里夺走
4. **循环等待条件**：存在一个线程等待循环，即每个线程都在等待下一个线程所持有的资源

### 死锁原因

1. **资源竞争**：共享资源数量不足，多个进程/线程争夺资源
2. **进程推进顺序不当**：请求和释放资源的顺序不恰当
3. **线程同步问题**：如多个线程获取锁的顺序不一致

### 死锁解决方法

#### 1. 死锁预防（破坏必要条件）

- **破坏"请求和保持"条件**：
  - 让进程一次性申请所有需要的资源（如果资源不足则等待）
  - 要求进程在申请资源前释放已持有的资源
- **破坏"不可剥夺"条件**：
  - 允许优先级高的进程抢占资源
  - 设置资源抢占机制
- **破坏"循环等待"条件**：
  - 给系统中的所有资源统一编号
  - 要求进程按资源编号顺序申请资源（如 A→B→C）

#### 2. 死锁避免

- 使用银行家算法等资源分配算法
- 保证多个线程/进程的执行顺序相同（如都按 A→B→C 顺序操作资源）

#### 3. 死锁检测与解除

- 定期检测系统是否处于死锁状态
- 通过检测工具（如 jstack）定位死锁线程
- 采用资源剥夺、进程回滚等策略解除死锁

#### 4. 死锁恢复

- 终止（或撤销）系统中的一个或多个死锁进程
- 重启系统（在严重情况下）
- 重新分配资源

### 实际应用示例

在数据库操作中，若事务 1 持有资源 A 的锁，尝试获取资源 B 的锁；事务 2 持有资源 B 的锁，尝试获取资源 A 的锁，就会发生死锁。解决方法是保证所有事务按相同顺序操作资源，如都先操作 A 再操作 B。

> **重要提示**：死锁是一种严重的并发问题，会导致系统资源浪费、程序响应停止和系统性能下降。在多线程开发中，应注重预防死锁，而不是事后补救。
