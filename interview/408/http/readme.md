# OSI 七层协议

## http 3.0 为啥可以解决队头阻塞问题

因为 HTTP/3 基于 QUIC（运行在 UDP 之上），QUIC 提供了多路独立的流，每个流独立丢包、独立重传，不会像 TCP 那样同一连接上的丢包导致所有数据都等待重传确认，从而消除了连接级队头阻塞（HOL）。此外，QUIC 将 TLS1.3 集成进握手并支持 0-RTT，降低时延。

## HTTP/1.1 vs HTTP/2 vs HTTP/3 速查表

### HTTP/1.1 关键特性

- 长连接（keep-alive）默认开启
- 可选管线化（易 HOL，多数禁用）
- 分块传输（Transfer-Encoding: chunked）
- 完整缓存与条件请求（Cache-Control / ETag / Last-Modified 等）
- 必须 Host 头；支持虚拟主机
- 纯文本头部，无压缩；无内建加密（依赖 HTTPS）

### HTTP/2 关键特性（相对 1.1）

- 二进制分帧
- 多路复用：一个 TCP 连接并行多流（缓解但未根除 HOL）
- HPACK 头部压缩
- 流优先级与依赖、流量控制
- Server Push（已不推荐，改用 preload/103）
- 实际部署常走 TLS+ALPN（h2）

### HTTP/3 关键特性（相对 2）

- 基于 QUIC/UDP，内置 TLS1.3，支持 0-RTT
- 真正消除连接级 HOL：流独立丢包与重传
- 连接迁移（Connection ID），移动网络切换不断连
- QPACK 头部压缩，避免头阻塞
- 通过 ALPN 协商 h3，可与 h2/1.1 回退共存

### 常见问题与实践建议

- 服务端开启 h3 同时保留 h2/1.1 回退；放通 UDP/443
- 前端不要再进行域名分片/雪碧图/过度内联，让协议多路复用与优先级生效
- 监控弱网指标：握手成功率、0-RTT 命中、丢包/重传、连接迁移、RTT/吞吐

### 对比一览

| 维度        | HTTP/1.1               | HTTP/2                  | HTTP/3                              |
| ----------- | ---------------------- | ----------------------- | ----------------------------------- |
| 传输基础    | TCP                    | TCP（二进制分帧）       | QUIC/UDP（用户态协议）              |
| 多路复用    | 否（可管线化但易 HOL） | 是（仍受 TCP 丢包牵连） | 是（流独立，无连接级 HOL）          |
| 头部压缩    | 否                     | HPACK                   | QPACK                               |
| 握手时延    | TCP + TLS 分层         | 同左                    | TLS1.3 内置于 QUIC，支持 0-RTT      |
| 连接迁移    | 否                     | 否                      | 是（Connection ID）                 |
| Server Push | 无                     | 有（已不推荐）          | 有（不推荐）                        |
| 部署难点    | 较低                   | 需 ALPN、证书优化       | 需 UDP/443、网关/CDN 支持、性能调优 |
