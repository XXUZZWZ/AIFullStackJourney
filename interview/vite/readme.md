### 简短结论

- 在移动网络与中端机上，用户通常在首屏资源压缩后超过约 200 KB 时开始明显“感觉慢”。

### 更可执行的阈值建议

- 关键路径资源（HTML + 首屏 CSS + 首屏 JS，gzip/br 后）：尽量 ≤ 150–200 KB
- 单个关键文件：建议 ≤ 50 KB（首屏 CSS/JS 各自不超过这个量更稳）
- 首屏图片总体：≤ 150–300 KB（WebP/AVIF，懒加载非首屏）
- 总 JS（gzip 后，含框架与业务）：≤ 200 KB；超过 300–400 KB 常见解析/编译卡顿
- 整页总传输体积（首屏+非首屏懒加载前）：≤ 1 MB；> 2 MB 多数用户会感觉慢

### 体验参考指标（以感知为准）

- TTFB ≤ 800 ms
- LCP ≤ 2.5 s（理想 ≤ 1.8–2.0 s）
- INP/FID ≤ 200 ms

小贴士：

- 用代码分割、延迟加载与预加载只保留“首屏必需”资源在 200 KB 内。
- 图片优先 WebP/AVIF，严格懒加载非首屏。
- 控制第三方脚本与未使用的 JS/CSS。
